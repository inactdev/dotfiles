# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Nix/home-manager entry points: `flake.nix` (hosts: `darwinConfigurations.personal-mac`, `homeConfigurations.home-linux`), `configuration.nix` (Darwin-only: system + Homebrew), `home.nix` (packages, dotfile symlinks, launchd agents - shared by both hosts). Apply with `./run.sh rebuild` (see `./run.sh help`); `nix eval --impure --expr '(builtins.getFlake (toString ./.)).darwinConfigurations.personal-mac.config...'` (swap in `.homeConfigurations.home-linux.config` for the Linux side) lets you check that an option evaluates without building or switching anything - `nix build` on the Linux side will fail on a non-x86_64-linux machine with a platform-mismatch error, which is expected; eval succeeding is the real check.
- `home.nix` is one shared module gated with `pkgs.stdenv.isDarwin` (see the `lib.mkMerge` blocks), not two files - Darwin-only pieces (launchd, herdr) live in an `isDarwin` block, Linux-only pieces (Nerd Font via an explicit `home.activation` script into `~/.local/share/fonts` + `fc-cache`) live in a `!isDarwin` block. Adding something Mac-only or Linux-only means a new block here, not a new file.
- Most of `home/**` is symlinked into `$HOME` via `mkOutOfStoreSymlink` in `home.nix` - editing the symlinked path IS editing the repo; nothing needs re-copying.
- Herdr plugins (`herdr plugin ...`) cannot host a long-running/daemon process: startup hooks are one-shot and must exit, and `[[panes]]` are user-facing terminal surfaces, not hidden background workers. Anything that needs to react continuously (e.g. polling `herdr agent explain` for detection-rule changes) belongs in an external script driven by a home-manager `launchd.agents` entry, not a plugin - see `home/.local/bin/herdr-agent-handoff-marker` and its `launchd.agents` block in `home.nix` for the pattern. Verify that script only with `sh home/.local/bin/herdr-agent-handoff-marker.test.sh`, which runs it against a mocked `herdr` on a hermetic PATH: never run it (or any `herdr tab rename`) against the live daemon, which would repaint the owner's real tabs. The hourglass mark is scoped to crewmate task tabs only (label convention `fm-<id>`, matching firstmate's own crewmate spawn labeling in the firstmate repo's `backends/herdr.sh`) - herdr's detection rule is pure content screen-scraping with no notion of tab role, so the marker script itself is the only place that knows a primary/secondmate tab must never be marked, and it self-heals a stray mark found on a non-`fm-*` tab regardless of that tab's handoff state.
- `run.sh` supports three hosts: `personal-mac` and `home-linux` (both Nix + home-manager) and `work` (plain Homebrew, no Nix - see the work-host section in `README.md`). With no explicit host/flags, `run.sh` asks once via an interactive menu; a "home" answer auto-detects Mac vs Linux from `uname -s` rather than asking, and a "work" answer on Linux fails immediately (there is no work-linux host - see the codespaces bullet below). The answer is remembered in `.dotfiles-host` (gitignored, per-clone); `./run.sh choose` re-asks. `run.sh` sources cleanly (see the `BASH_SOURCE` guard at its tail) so `run.test.sh` can call its functions directly against a mocked `uname` - run with `bash run.test.sh`. Everything for the work host lives under `work/`: `work/bootstrap.sh` does the installing/linking/configuring and is idempotent, `work/Brewfile` is the exact package manifest, `work/zshrc` is the work host's real `~/.zshrc`, `work/claude-settings.json` is `home/.claude/settings.json` with `hooks`/`skipDangerousModePermissionPrompt` stripped (re-derive with the `jq` command in README.md after editing the source file). Verify `work/bootstrap.sh` only with `sh work/bootstrap.test.sh`, which mocks `brew`/`defaults`/`killall`/`gh` on a hermetic PATH and a scratch `$HOME` - never run the real script against this machine's real Homebrew/macOS defaults/`~/.claude` from a dev/test session.
- GitHub Codespaces is a fourth, script-only host: GitHub auto-clones this repo and runs `install.sh` (the first name it checks in its fixed setup-script filename list) fully non-interactively - it requires `CODESPACES=true` and never goes through `run.sh`'s menu. Personal-vs-work posture is structural: it compares `$GITHUB_REPOSITORY`'s owner against this repo's own `git remote get-url origin` owner (same owner = personal; anything else, including undeterminable, = the locked-down work default) - see `detect_posture` in `install.sh`. `codespaces/claude-settings.json` and `work/claude-settings.json` are both `home/.claude/settings.json` with the axi-tool hooks stripped (those tools aren't installed in a codespace either way); only the work variant additionally drops `skipDangerousModePermissionPrompt`. Verify the decision logic with `bash install.test.sh` (hermetic, no apt/npm/network); verify the real install with `docker run --platform linux/amd64 ubuntu:24.04` (real Codespaces machines are x86_64, so force the platform on Apple Silicon) - clone via `git bundle create`, not `cp -r` or a plain local-path clone, since this repo is normally checked out as a linked worktree whose `.git` is a pointer file to an absolute host path that doesn't exist inside the container.
- `set -e` pitfall specific to this repo's scripts: a bare `[ cond ] && cmd` (not wrapped in `if`) that evaluates false is normally harmless mid-script, but if it's the *last* command a script executes (e.g. the final line of a function called last in `main`), its exit status becomes the whole script's exit status - so it silently fails even though every step succeeded. Use `if`/`fi` for any such check that could run last.
